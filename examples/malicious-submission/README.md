# Malicious submission

`overlay/bend2/opt/optimize.mjs` is hostile code placed where a competitor's optimizer goes. It
tries network access, reading SSH keys, rewriting the verifier and the reference compiler, env
secrets and a process bomb, then forges a certificate: it claims the pre-proven library rule
`fold` turned `run` into "return the benchmark answer" (a 10^9× "speedup").

Expected outcome (`examples/run-demo`, `tests/adversarial`):

* every escape attempt fails inside the locked-down container (see the attempt log below);
* verification fails at the **proof** stage: the obligation generated by the verifier asks the Lean
  kernel to evaluate the rule checker `applyStep`, which does not produce the claimed program, so the
  obligation module does not compile;
* the candidate is never benchmarked.

Try it:

```bash
./examples/materialize examples/malicious-submission work/ex-mal
./competitor-sdk/tools/prove-candidate work/ex-mal --no-prove
./scripts/package-submission work/ex-mal -o work/mal.tar.zst
./scripts/run-contest work/mal.tar.zst
```

`competitor-sdk/tools/prove-candidate --no-prove` warns that the obligation does not compile but still
writes `submission.json`: the SDK is advisory, and a hostile miner would skip it anyway.
